# Cybersecurity Playbook Structure for SMEs

## 1. Assess

Purpose: Understand the company’s current cybersecurity posture, business risks, and readiness level.

### 1.1 Business Context Assessment

Define what the business does, what systems support operations, what data matters most, and which processes must keep running during disruption.

### 1.2 Cybersecurity Maturity Assessment

Review the current state of security controls across people, process, and technology.

Include:

MFA coverage  
Backup maturity  
Endpoint protection  
Patch management  
Email security  
Vendor security  
Incident response readiness  
Employee awareness

### 1.3 Risk Assessment

Identify the most likely and most damaging cyber scenarios for the SME.

Examples:

Business email compromise  
Ransomware  
Credential theft  
Cloud account takeover  
Lost or stolen laptop  
Invoice fraud  
Data breach  
Website compromise  
Third-party compromise

### 1.4 Compliance and Contractual Assessment

List applicable obligations from clients, regulators, insurers, and industry standards.

### 1.5 Gap Analysis

Compare current controls against the desired minimum security baseline.

Output of this phase:

Current-state assessment  
Risk register  
Critical gaps list  
Initial security priorities

## 2. Identify

Purpose: Know exactly what needs to be protected.

### 2.1 Asset Inventory

Create and maintain a list of company-owned and business-critical assets.

Include:

Laptops and desktops  
Servers  
Mobile devices  
Network devices  
Cloud platforms  
SaaS applications  
Websites and domains  
Business applications

### 2.2 Data Inventory

Identify what sensitive data the company stores, processes, or shares.

Include:

Customer data  
Employee data  
Financial records  
Contracts  
Intellectual property  
Credentials  
Business plans  
Operational data

### 2.3 Account and Access Inventory

List all user accounts, admin accounts, shared accounts, service accounts, and third-party accounts.

### 2.4 Critical Business Process Mapping

Map which systems support core business activities.

Examples:

Sales  
Accounting  
Payroll  
Customer support  
Operations  
Procurement  
Inventory  
Email communication

### 2.5 Third-Party Inventory

List vendors, SaaS providers, IT providers, MSPs, payment processors, and contractors with access to systems or data.

Output of this phase:

Asset inventory  
Data inventory  
Account inventory  
Critical systems list  
Vendor inventory

## 3. Protect

Purpose: Put controls in place to reduce the chance and impact of cyber incidents.

### 3.1 Identity and Access Protection

Define access control standards.

Include:

MFA requirements  
Password manager use  
Least privilege access  
Admin account restrictions  
Access approval process  
Access removal process  
Quarterly access reviews

### 3.2 Endpoint Protection

Protect laptops, desktops, servers, and mobile devices.

Include:

Antivirus or EDR  
Disk encryption  
Automatic updates  
Screen lock  
Device hardening  
Lost device procedure  
Local admin restrictions

### 3.3 Email and Phishing Protection

Reduce phishing, impersonation, and business email compromise risk.

Include:

SPF, DKIM, and DMARC  
Email filtering  
Phishing report process  
Payment change verification  
Attachment handling rules  
Executive impersonation controls

### 3.4 Network Protection

Secure the company’s network and remote access.

Include:

Firewall configuration  
Secure Wi-Fi  
Guest network separation  
VPN requirements  
Network segmentation  
Router admin controls  
Secure DNS filtering

### 3.5 Cloud and SaaS Protection

Secure Microsoft 365, Google Workspace, CRM, accounting software, file-sharing tools, and other SaaS platforms.

Include:

MFA for admins  
External sharing controls  
Audit logging  
User provisioning  
User deprovisioning  
Admin role control  
Backup settings

### 3.6 Data Protection

Set rules for how sensitive information is stored, shared, retained, and deleted.

Include:

Data classification  
Encryption  
Secure file sharing  
Retention rules  
Secure deletion  
Data loss prevention basics

### 3.7 Backup Protection

Define how backups are created, stored, protected, and tested.

Include:

Backup frequency  
Backup scope  
Offline or immutable backups  
SaaS backups  
Backup encryption  
Restore testing

Output of this phase:

Security policies  
Control implementation checklist  
Access control rules  
Backup plan  
Cloud/SaaS security baseline

## 4. Detect

Purpose: Find suspicious activity early before it becomes a major incident.

### 4.1 Logging and Monitoring

Define what activity must be logged.

Include:

Email logins  
Admin activity  
Failed login attempts  
Endpoint alerts  
Firewall alerts  
Cloud/SaaS activity  
File-sharing activity

### 4.2 Alerting Rules

Define which events require review or escalation.

Examples:

Multiple failed logins  
Login from unusual country  
New admin account created  
Large data download  
Disabled MFA  
Endpoint malware alert  
Suspicious mailbox forwarding rule  
Unexpected payment detail change

### 4.3 Vulnerability Detection

Set a process for identifying technical weaknesses.

Include:

Patch status review  
External vulnerability scan  
Endpoint health check  
Cloud configuration review  
Website security review

### 4.4 Employee Reporting

Create a simple reporting path for employees to report suspicious activity.

Examples:

Suspicious email  
Lost device  
Accidental data sharing  
Strange login notification  
Unexpected invoice request

### 4.5 Detection Ownership

Define who receives alerts, who investigates them, and when escalation is required.

Output of this phase:

Monitoring checklist  
Alert rules  
Reporting process  
Detection escalation path  
Vulnerability findings list

## 5. Respond

Purpose: Contain and manage cybersecurity incidents quickly and correctly.

### 5.1 Incident Classification

Define what counts as an incident and how severe it is.

Severity levels:

Low: suspicious email, blocked malware  
Medium: compromised user account, lost device  
High: confirmed malware, data exposure  
Critical: ransomware, financial fraud, major system compromise

### 5.2 Incident Response Roles

Assign clear responsibilities.

Include:

Business owner  
IT lead or MSP  
Legal contact  
Cyber insurance contact  
Communications lead  
Finance lead  
External incident response provider

### 5.3 First-Hour Response Checklist

Define immediate actions.

Include:

Confirm the incident  
Preserve evidence  
Disable affected accounts  
Disconnect infected devices  
Block malicious domains or IPs  
Notify leadership  
Start incident log  
Contact insurer if required

### 5.4 Incident-Specific Playbooks

Create separate response steps for the most likely SME incidents.

Include:

Phishing email  
Compromised email account  
Ransomware  
Lost or stolen device  
Malware infection  
Business email compromise  
Invoice fraud  
Data breach  
Cloud account compromise  
Website compromise

### 5.5 Communication Plan

Define who must be notified and when.

Include:

Internal leadership  
Employees  
Customers  
Vendors  
Cyber insurer  
Legal counsel  
Regulators  
Law enforcement

### 5.6 Evidence and Documentation

Document what happened, when it happened, who was involved, what actions were taken, and what evidence was preserved.

Output of this phase:

Incident response plan  
Role assignment matrix  
First-hour checklist  
Incident-specific response procedures  
Incident log template

Purpose: Restore business operations safely and prevent immediate reinfection or repeat compromise.

### 6.1 Recovery Prioritization

Examples:

Accounting  
File storage

CRM

E-commerce site  
Operational systems

### 6.2 System Restoration

Define how systems are rebuilt, restored, or replaced.

Include:

Restore from clean backups  
Rebuild infected devices  
Reset passwords  
Reissue credentials  
Patch exploited systems  
Validate configurations  
Monitor restored systems

### 6.3 Data Restoration

Recover lost, encrypted, deleted, or corrupted data.

Include:

Backup validation  
Restore testing  
Data integrity checks

### 6.4 Business Continuity

Examples:

Increase monitoring after recovery to confirm the attacker is no longer active.

Include:

Endpoint scans  
Mailbox rule reviews

Network traffic review

Output of this phase:

Recovery plan  
System restoration checklist  
Business continuity procedure  
Backup restore report  
Post-recovery validation checklist

## 7. Review

Purpose: Learn from assessments, incidents, tests, and operational changes.

### 7.1 Post-Incident Review

After every major incident, answer:

What happened?  
How was it detected?  
What failed?  
What worked?  
What was the business impact?  
What controls need improvement?  
Who owns each corrective action?

### 7.2 Quarterly Security Review

Review security posture every quarter.

Include:

Open risks  
Patch status  
MFA coverage  
Backup test results  
Incidents and alerts  
Vendor changes  
New systems  
Employee access changes

### 7.3 Annual Playbook Review

Review and update the full playbook annually.

Include:

Business changes  
Technology changes  
New legal or contractual requirements  
Lessons learned  
Control maturity  
Budget priorities

### 7.4 Tabletop Exercises

Run practical simulations.

Suggested scenarios:

Ransomware attack  
Compromised CEO email  
Lost laptop with customer data  
Fake invoice payment  
Cloud account takeover  
Major SaaS outage

### 7.5 Metrics and Improvement Plan

Track a small set of useful metrics.

Include:

MFA coverage percentage  
Backup success rate  
Restore test success rate  
Critical patch completion time  
Number of phishing reports  
Number of unresolved risks  
Mean time to respond  
Training completion rate

Output of this phase:

Lessons learned report  
Updated risk register  
Updated playbook  
Corrective action tracker  
Security improvement roadmap

# Recommended Iterative Process

The full playbook should operate as a cycle:

Assess current risk.  
Identify assets, data, accounts, and vendors.  
Protect the most important systems first.  
Detect suspicious activity early.  
Respond quickly when incidents happen.  
Recover safely and restore operations.  
Review what worked and what failed.  
Educate employees continuously.  
Repeat the cycle quarterly.

My blunt recommendation: put “Educate” at the end of the cycle, but do not treat it as the last priority. Training should run throughout the whole process. Also, “Assess” and “Identify” must be separated. Many companies merge them, and that creates a weak playbook because risk assessment and asset discovery are not the same job.
